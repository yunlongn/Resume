  • Project. 项目经历

    • 洋葱集团 - 商城支付中心

      项目介绍： 负责商城支付中心交易、退款业务的开发与维护， 支撑多支付渠道统一接入、交易预支付、支付回调、 退款处理及异步订单状态查询等核心业务。 项目采用微服务架构，支持多渠道支付路由、 统一支付接口及分布式部署。

      技术架构： Spring Boot、Spring MVC、MyBatis、Redis、 MQ、Sentinel、Kubernetes（K8s）、ConfigMap。

      部署架构： 项目部署于 Kubernetes 集群， 通过 ConfigMap 实现应用配置管理， 多个 Service 及 Node 节点提供服务， 支持支付接口集群化部署及横向扩展。

      核心工作与技术贡献：

      1、自研支付路由与渠道扩展机制： 设计并实现基于注解驱动的支付渠道扩展框架， 通过 @PayService 按支付渠道、境内外等维度注册实现类， 通过 @PayOperate 映射支付操作类型， 由统一入口动态匹配并调用对应支付实现。 同时封装参数解析、请求与响应转换、调用过滤器等通用处理流程， 实现支付渠道与核心业务解耦。 新增支付渠道只需按照既定接口扩展实现类， 减少渠道判断逻辑在统一 API 中的分散，提高系统可扩展性及维护效率。

      2、支付回调与异步查单的可恢复重试机制： 基于自研 delay-scheduler 延迟任务调度器， 实现支付回调、退款回调及异步订单查单的延迟调度与分段重试， 支持自定义重试周期及任务参数持久化。 任务状态及相关参数存储于 Redis， 当集群节点异常或任务执行中断时， 支持根据任务记录重新提交未完成任务， 结合业务幂等机制避免重复执行带来的数据异常。 支付回调链路采用先更新订单状态、再通知商户的处理流程， 提高支付结果处理的可靠性及异常恢复能力。

      3、基于 Sentinel 的配置化开关与降级机制： 在 Sentinel 原有熔断降级能力基础上进行扩展， 实现资源级开关规则，支持通过配置动态控制指定接口的启用与降级。 配置变更后自动刷新并重新加载规则， 无需修改业务代码及重新发布应用即可调整接口降级策略， 提高系统应对渠道异常及突发业务问题的灵活性。

      4、多渠道支付接入与支付分流： 负责数字人民币及其他支付渠道的接入开发， 完成支付请求、交易结果及回调接口对接。 基于订单 ID 取模分流算法， 实现多支付渠道按比例分配交易请求， 支持支付流量灵活分配及渠道分流策略。

      5、Redis 与 MQ 多数据源扩展： 针对项目多 Redis、多 MQ 数据源的使用场景， 自定义实现 @RedisAutowired 注入机制。 通过 BeanDefinitionRegistryPostProcessor 将数据源注册至 Spring Bean 容器， 在 Bean 属性填充阶段扫描指定注解并完成目标数据源注入， 实现多数据源的灵活切换与统一管理， 降低业务代码对具体数据源的依赖。

    • 定时任务调度平台（XXL-JOB）

      项目介绍： 基于 XXL-JOB 构建统一定时任务调度平台， 对原有分散在各业务系统中的定时任务进行集中化管理与业务解耦， 统一承载业务跑批、数据处理及定时任务执行， 提高定时任务的可维护性、执行效率及系统扩展能力。

      技术架构： Spring、Spring MVC、MyBatis、Redis、XXL-JOB、Elasticsearch、多线程并发处理。

      核心工作与技术贡献：

      1、定时任务开发与维护： 负责平台新增定时任务需求的开发及旧任务的 Bug 修复， 将原有分散于各业务系统的定时任务逐步迁移至统一调度平台， 实现定时任务集中管理、统一调度及业务逻辑解耦。

      2、基于 XXL-JOB 的分布式任务分片： 利用 XXL-JOB 分片广播机制， 将整月业务数据按照分片规则分配至多台执行节点， 实现多节点并行跑批， 提升大批量数据处理能力及定时任务执行效率。

      3、自研异步分片处理组件 AsyncShardingHandle： 针对大批量 List 数据处理场景， 自主设计并实现基于异步线程池 + 数据分片的并发处理组件， 将原有串行 IO 密集型任务改造为多线程并发执行， 支持 List 数据自动分片及异步任务处理， 提高批量数据处理效率， 跑批效率提升 50% 以上。 并将组件开源发布至 Maven 中央仓库， 提高组件复用能力。

      4、物流查询业务优化与订阅化改造： 负责物流查询模块的架构优化， 将原有主动轮询物流轨迹的模式改造为物流订阅 + 回调通知模式， 接收物流服务商推送的轨迹数据， 并将物流轨迹写入 Elasticsearch（ES） 进行存储与缓存， 减少重复物流查询请求及第三方接口调用， 每月物流查询费用降低 20%。

      开源项目： AsyncShardingHandle（异步分片处理组件） https://search.maven.org/artifact/io.gitee.yunlongn/yunlongn-async
